# Panduan agen: Warehouse FTV / Gearent

Dokumen ini adalah peta kerja untuk agen yang mengubah repositori ini. Baca bagian yang relevan sebelum mengedit. Ini disusun dari kode, konfigurasi, migrasi, dan Git pada 2026-09-17. **Kode saat ini adalah sumber kebenaran** jika dokumen lama berbeda. Perbarui peta ini saat struktur atau aturan bisnis berubah.

## Identitas dan teknologi

- Satu codebase melayani panel admin `/admin` dan storefront pelanggan. Nama produk di kode/dokumen adalah **Gearent**; identitas penerapan ini adalah **Warehouse FTV UPI**. Nama lama "Zewalo" masih dapat muncul di dokumen atau nama CSS.
- Backend: PHP `^8.2`, Laravel `^12`, Filament `^4`, Livewire, Blade, Eloquent. Admin memakai Filament Resources/Pages/Clusters/Widgets; frontend memakai controller Laravel dan Blade. CMS memakai LaraZeus Sky, izin admin memakai Filament Shield.
- Aset web: Vite 7, Tailwind 4, Alpine, JavaScript. Input Vite ada di `vite.config.js`: `resources/css/app.css`, `resources/js/app.js`, `resources/js/unit-scanner.js`, dan `resources/css/filament/admin/theme.css`.
- Aplikasi desktop kiosk adalah package Electron tersendiri di `desktop-kiosk/`, tetapi **bukan repo Git terpisah**.
- Default `.env.example`: SQLite, serta session/queue/cache driver database. `phpunit.xml` memakai SQLite `:memory:` dengan session array dan queue sync. `phpunit.mysql.xml` tersedia untuk pengujian MySQL.

## Boot, rute, dan autentikasi

- `routes/web.php` dibungkus pemeriksaan `storage/installed`. Tanpa marker, aplikasi hanya mendaftarkan rute wizard `/setup`; rute normal berada di cabang `else`. Tambahkan rute aplikasi baru di cabang yang benar. `SetupController` membuat marker tersebut.
- Panel Filament didaftarkan di `app/Providers/Filament/AdminPanelProvider.php`, ID/path `admin`; resource, cluster, halaman, dan widget ditemukan otomatis. Rute web eksplisit untuk fitur admin seperti label, scanner, PWA, dokumen, impersonasi ada di `routes/web.php` dan memakai middleware masing-masing.
- Storefront publik: `/`, `/schedule`, `/catalog`, `/computers`, `/kiosk/checkin/{slug}`. Rute `customer.auth` mencakup `/customer/*`, cart, checkout, serta dokumen pelanggan. `/login` dan `/register` pelanggan ditangani `CustomerAuthController` melalui `customer.guest`. Admin memakai auth Filament.
- `User`/`user_id` adalah identitas bersama admin dan pelanggan. Jangan memakai `customer_id` lama untuk relasi rental; pengguna yang sama dapat menjadi admin dan pelanggan. Periksa policy dan Shield untuk otorisasi. Ada banyak policy lokal di `app/Policies/`, bukan hanya `CartPolicy`.
- `AppServiceProvider::boot()` memasang observer, listener push, view composer PDF/tema, timezone dari setting `app_timezone` (fallback Asia/Jakarta), dan `URL::forceScheme('https')`. URL lokal HTTP dapat dihasilkan sebagai HTTPS.
- Setting runtime tersimpan sebagai key/value di `App\Models\Setting`. Cek nama key dan fallback pada halaman setting serta konsumen sebelum mengubah perilaku.

## Inventaris, ketersediaan, dan rental

- Hirarki stok: `Product` → `ProductVariation` opsional → `ProductUnit` (unit fisik/serial yang dijadwalkan) → `UnitKit` (aksesori). RentalItem biasanya menunjuk unit fisik, tetapi product_unit_id dapat kosong sebagai ghost slot. UI memakai `composite_id` `{product_id}` atau `{product_id}:{variation_id}`.
- `UnitKit` yang `track_by_serial` dapat dihubungkan ke bayangan `ProductUnit` lewat `KitUnitLinker` dan `linked_unit_id`. `UnitKitObserver` menjaga tautan dan menolak serial yang merujuk unit induk/salah produk. `ProductUnitObserver` menyinkronkan serial kit tertaut saat serial unit berubah. Jangan mengubah serial via SQL mentah tanpa meninjau observer.
- Validasi tanggal, bentrok unit, jadwal operasional, hari libur, dan `Product.buffer_time` berpusat di `RentalValidationService`. Alur admin (`app/Filament/Resources/Rentals/` dan `RentalEditor`) serta storefront (`CheckoutController`, `CatalogController::checkAvailability`) harus tetap konsisten. `ProductUnit` adalah unit yang diblokir saat dijadwalkan. Status rental `expired`/`cancelled` tidak memblokir ketersediaan.
- Status di `Rental`: `quotation`, `confirmed`, `active`, `completed`, `cancelled`, `late_pickup`, `late_return`, `partial_return`, `expired`. `quotation` yang melewati start menjadi `expired`; **hanya** `confirmed` yang menjadi `late_pickup`; `active`/`partial_return` yang lewat end menjadi `late_return`. Jaga keselarasan `CheckLateRentals`, `Rental::getRealTimeStatus()`, dan `Rental::checkAndUpdateLateStatus()`. `completed`/`cancelled`/`expired` tidak ikut transisi otomatis. Untuk menghidupkan `expired`, admin mengedit tanggal pickup/return ke masa depan serta item jika perlu, lalu memakai aksi Reopen di daftar/detail rental; status kembali `quotation` dan perlu Confirm lagi. `completed` dan `cancelled` terkunci.
- Saat menambah status, periksa `Rental::getStatus*()`, filter/tabel, Blade, kalender admin dan storefront, serta setiap `match` tanpa default. Ada beberapa permukaan kalender: `Filament/Pages/Schedule.php`, `GlobalProductSchedule.php`, `RentalCalendar.php`/widget, `Frontend/ScheduleController.php`, dan kalender detail produk.
- Halaman create/edit rental **bukan form Filament biasa**: halaman resource membungkus `filament.rentals.editor` dan komponen `App\Livewire\Admin\RentalEditor`. Item UI dikelompokkan menurut produk/variasi, sementara `RentalItem` tetap satu per unit; `RentalForm::groupItemsForForm()`/`syncRentalItems()` menghubungkan keduanya. `ItemsRelationManager` masih ada tetapi tidak dipakai di editor baru. Tambahkan UI/alur item di Livewire + Blade editor. Slot unit kosong tetap boleh dibuat agar admin dapat melakukan transfer.
- `RentalItem::$touches = ['rental']` menjalankan `RentalObserver` untuk menghitung ulang setelah perubahan item. Jangan melakukan recalc manual berulang tanpa menelusuri observer. `RentalItemTransferService` melakukan MOVE/SWAP/PULL dalam transaksi: MOVE memindahkan assignment `product_unit_id`, meninggalkan **ghost slot** di rental sumber, dan mengisi ghost slot tujuan yang cocok bila ada; SWAP menukar unit. Hanya `quotation`/`confirmed`/`late_pickup` boleh ditransfer. Catat tindakan lewat `Rental::logActivity()` pada JSON `activity_log`, bukan menempelkan audit ke `notes`.
- Pickup/return fisik berada di `Filament/Resources/Rentals/Pages/PickupOperation.php` dan `ProcessReturn.php`, dengan `Delivery`/`DeliveryItem` sebagai catatan keluar/masuk. `delivery_items.not_taken` hanya milik baris aksesori pada delivery OUT; aksesori yang tidak diambil dihilangkan dari checklist IN oleh `Rental::createDeliveries()`. Scanner operasi memakai `resources/js/unit-scanner.js`, `@zxing/browser`, dan `UnitCodeService` (`PREFIX:serial`, QR dan Code128 sama). Label PNG server memakai `LabelImageService` dan GD.
- Denda terlambat otoritatif pada `rentals.late_fee`; nilai `invoices.late_fee`/`total` diturunkan ulang oleh `Invoice::recalculate()`. `Rental::calculateOverdueFee()` membaca mode/setting denda. Return, action Add Late Fee, dan penyesuaian diskon harus mengikuti `Rental::recalculateTotal()` serta `Rental::syncOutstandingInvoice()` agar piutang terbarui. Pembayaran dicatat lewat action/alur invoice dan `FinanceTransaction`; denda tidak otomatis menjadi lunas. `Rental::reopenFromCompleted()` mengubah operasi/delivery, tetapi tidak membalik jurnal lama; periksa dampak akuntansinya sebelum memakainya untuk perubahan nilai.
- Diskon rental terdiri dari diskon kategori pelanggan, `DailyDiscount`, `DatePromotion`, dan diskon manual/kupon. `Rental::discountBreakdown()` menjadi sumber rincian UI/PDF. Harga item/cart tetap bruto; diskon kategori adalah baris tersendiri. `discount` manual dan kupon berbagi kolom dan saling menggantikan.
- Fitur terbaru (migrasi `2026_07_04_*`): harga per jam/hari/minggu/bulan pada produk/variasi; `rentals.pricing_period` dan `rental_items.rate_type` menyimpan periode terpilih, sementara nama kolom lama `daily_rate`/`days` berarti tarif/jumlah **periode**. Rental berulang menghasilkan quotation baru lewat `rentals:generate-recurring` tanpa auto-charge. `fulfillment_method` menentukan pickup/delivery, dengan alamat dan kontak pada rental serta driver/pengawal/jadwal/alamat pada delivery. `Product`/`Rental` punya `custom_fields` JSON, definisinya di setting `product_custom_fields`/`rental_custom_fields`.

## Penjualan, akuntansi, dan laporan

- Resource `Invoices` dan `Quotations` ada di `app/Filament/Resources/`; action bersama di `app/Filament/Actions/` (`RecordPaymentAction`, `AddLateFeeAction`, `ConvertQuotationToInvoiceAction`, `AdjustDiscountAction`, deposit/refund). Pakai action bersama agar tabel, halaman detail, dan Accounts Receivable konsisten. `Invoice::recalculate()` dan atribut balance menentukan status/jumlah; cek implementasi aktual sebelum menambah kalkulasi di UI.
- Finance dapat berada dalam mode `simple` atau `advanced`. Posting GL sewa saat ini berpusat di `RentalAccountingService`; utang/AP di `PayableAccountingService`. `JournalService` menangani jurnal dan validasi balance/periode tutup. Jangan menghidupkan lagi pola lama `JournalService::recordSimpleTransaction()` untuk event siklus rental tanpa menelusuri service baru, karena pernah menyebabkan pengakuan pendapatan ganda.
- Setting `accounting_standard`: `sak` mengakui pendapatan saat invoice; `ifrs` menunda hingga rental selesai. Service memastikan pengakuan sekali dan mengecualikan security deposit dari pendapatan. `JournalEntryItemObserver` dan `FinanceTransactionObserver` menjaga efek samping ledger. Hindari raw write yang melompati mereka.
- `Finance/Pages/LedgerReports.php` dan `LedgerReportService` membuat laporan dari jurnal; `FinancialReports.php` memakai agregat operasional. `AgingReportService`, `TaxReportService`, rekonsiliasi bank, depresiasi per unit, PPh23, dan dasar multi-currency ada di `app/Services/` serta migrasi `2026_07_01_*`. GL tetap dalam base currency; rental FX per baris/revaluasi periode belum dibangun.

## Komputer, kiosk, PWA, CMS, dan label printer

- Booking komputer adalah domain terpisah dari rental/finance, tetapi berbagi `users`, auth pelanggan, admin panel, dan `Setting`. Model: `ComputerRoom`, `Computer`, `ComputerBooking`, `ComputerBookingSlot`, `ComputerMaintenanceLog`. Validasi bentrok, maintenance, kuota, dan slot ada di `ComputerValidationService`; checkout booking pelanggan dan admin harus konsisten. Admin ada di `Clusters/Computers/`; setting aktual di `Clusters/Computers/Pages/BookingSettings.php`. Tidak ada `ComputerSlotResource` dalam kode saat peta ini dibuat.
- Kiosk web memakai `/kiosk/checkin/{slug}` dan controller `ComputerCheckinController`; API pairing/heartbeat/update di `/api/kiosk/*` dan `KioskApiController`, bearer middleware `KioskBearerAuth` untuk Electron. Aplikasi Electron di `desktop-kiosk/` melakukan pairing, heartbeat sekitar 30 detik, telemetry, update, dan command shutdown/restart yang diantrikan di `kiosk_commands`. Mac memakai browser kiosk + heartbeat web, tanpa akses proses OS/remote command. Detail setup di `desktop-kiosk/README.md` dan `setup_komputer.md`.
- Admin PWA (`AdminPwaController`, `WebPushService`, `SendWebPushOnNotification`) memiliki manifest/SW `/admin/*` sendiri; storefront memakai `public/manifest.json` dan `public/sw.js`. Kunci VAPID berada di env, jangan diputar ulang sembarangan karena subscription lama akan putus. `ADMIN_PWA_SETUP.md` berisi langkah penerapan.
- Label Bluetooth berada di `public/vendor/luckprinter/`: `editor.html` + `editor-app.js` adalah dokumen HTML tersendiri pada `/admin/print-label`, **bukan** komponen Filament/iframe dan **bukan** input Vite. Rute tersebut dan API unit/template/kalibrasi ada di `routes/web.php`; `LabelPrinter` hanya menyediakan tautan menu. Gunakan `UnitCodeService::encode()` sebagai isi QR/barcode dari data sistem, bukan serial mentah. Web Bluetooth memerlukan Chrome/Edge dan HTTPS/localhost.
- QR scanner admin global ada di `resources/views/filament/hooks/qr-scanner.blade.php`; pada layout sidebar sekarang dipasang di `panels::body.end` dan trigger di floating profile capsule. Ia menerima kode unit/kit dan mengarah ke produk lewat `/admin/scan-resolve`.
- CMS Sky terdaftar pada `AdminPanelProvider`; resource vendor disembunyikan dan diganti resource lokal `PostResource`, `PageResource`, `NavigationResource`, `TagResource`. Ubah resource lokal untuk kebutuhan CMS.
- Layout admin default sidebar; setting `navigation_layout='top'` memilih top nav. `resources/views/filament/hooks/responsive-navigation.blade.php` memberi class `body.gr-compact` bila portrait **atau** lebar <1024px; CSS compact dan bottom bar ada di hook dan `resources/css/filament/admin/theme.css`. Gunakan class itu untuk fitur UI baru yang mengikuti chrome compact. Halaman rental/view/pickup/return punya UI mobile dan action bar khusus. Tema primer dinamis lewat `ThemeService`, dipakai admin dan layout frontend.

## Command, verifikasi, dan lingkungan lokal

- `composer setup` memasang dependensi, membuat `.env`/key, migrasi, npm install, dan build; jalankan hanya ketika memang menyiapkan lingkungan. `composer dev` menjalankan server, queue listener, Pail, Vite. `npm run dev`/`npm run build` untuk aset. `composer test` membersihkan config lalu menjalankan tes; `vendor/bin/pint` untuk format.
- `routes/console.php` saat ini menjadwalkan `rentals:check-late` (5 menit), `app:send-rental-reminders` (harian pada setting `daily_reminder_time`, default **17:00**), `finance:run-depreciation` (akhir bulan 23:00), `computer-bookings:process` (5 menit), `maintenance:flag-due` (harian 08:00), dan `rentals:generate-recurring` (harian 06:00). Server tetap perlu menjalankan Laravel scheduler.
- Per 2026-09-17 `vendor/autoload.php` **ada** dan `storage/installed` **tidak ada** di checkout lokal. Cek ulang keadaan dependensi sebelum tes. Tanpa marker instalasi, rute aplikasi tidak terdaftar untuk pemeriksaan lokal. PHP CLI XAMPP berada di `C:\xampp\php\php.exe` (PHP tidak ada di PATH saat pemeriksaan); gunakan path itu bila tersedia. Periksa extension yang diperlukan, termasuk GD, sebelum menjalankan uji gambar/label. Untuk edit PHP, lint file berubah dengan `& 'C:\xampp\php\php.exe' -l path\to\file.php`, lalu jalankan tes yang terkait jika lingkungan mendukung. Jangan menjalankan `composer install/update` hanya untuk verifikasi kecil: hook `post-autoload-dump` menjalankan `filament:upgrade`.
- Tes yang ada: `tests/Unit/PartialReturnLateFeeTest.php`, `tests/Feature/FinanceTest.php`, `tests/Feature/Auth/*`, `ProfileTest`, dan contoh Laravel. Perluas tes untuk perubahan aturan bisnis yang berisiko; jangan menganggap cakupan lama melindungi seluruh modul. Untuk perubahan status, sapu semua `match`, switch Blade, badge, kalender, serta query whitelist status.
